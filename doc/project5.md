# 요구사항 분석서: 미니 드라이브(Mini Drive)

## 1. 서론

### 1.1 목적
본 문서는 사용자가 개인 파일을 안전하게 저장, 관리 및 공유할 수 있는 경량화된 클라우드 저장소 시스템인 **'Mini Drive'**의 요구사항 및 설계를 정의하기 위해 작성되었다.

### 1.2 용어 정의
- **Mini Drive:** 사용자의 파일을 저장하고 관리하는 가상의 저장 공간.
- **API:** 드라이브 시스템과 외부 어플리케이션 간의 상호작용을 위한 인터페이스.
- **스트리밍:** 대용량 파일 업로드/다운로드 시 데이터를 끊김 없이 전송하는 방식.

### 1.3 참조 문서
- 소프트웨어 공학 설계 원칙
- RESTful API 설계 가이드라인

## 2. 시스템 개요

### 2.1 액터 정의
| 액터명 | 역할 및 설명 |
| :--- | :--- |
| **관리자** | 시스템의 전체 리소스, 사용자 계정 및 파일 DB를 모니터링하고 제어함. |
| **사용자** | 파일을 업로드, 다운로드, 삭제 및 공유하는 서비스의 최종 이용자. |
| **외부 시스템** | 이메일 인증 서비스나 클라우드 백업 서버 등 연동되는 외부 모듈. |

#### 2.2.1 유스케이스 목록
- **U_01 회원가입:** 신규 사용자가 정보를 입력하여 계정을 생성한다.
- **U_02 로그인:** 기존 사용자가 인증을 통해 시스템에 접속한다.
- **U_03 파일 업로드:** 로컬 장치의 파일을 드라이브 서버로 전송한다.
- **U_04 드라이브 관리:** 파일 및 폴더의 이름 변경, 이동, 삭제를 수행한다.

## 3.3 동적 분석

1. **사용자** -> **UI**: 업로드 버튼 클릭 및 파일 선택
2. **UI** -> **Manager**: 파일 전송 요청
3. **Manager** -> **Drive DB**: 저장 경로 할당 및 가용 용량 확인
4. **Drive DB** -> **Manager**: 확인 결과 응답
5. **Manager** -> **Storage**: 물리적 파일 저장 수행
6. **Manager** -> **UI**: 업로드 완료 알림


## 4. 비기능 요구사항
- **보안:** 모든 파일 전송은 SSL/TLS 암호화를 통해 보호되어야 함.
- **성능:** 100MB 이하 파일 업로드 시 10초 이내에 완료되어야 함.
- **확장성:** 향후 구글 드라이브나 드롭박스 등 외부 클라우드 API와의 연동을 고려함.

## 5. 제약사항

1. **기술적 제약:** 시스템은 기존의 데이터베이스 구조와 호환되어야 하며, RESTful API 표준을 준수해야 한다.
2. **보안 제약:** 모든 파일 전송은 SSL/TLS 암호화 프로토콜을 거쳐야 하며, 사용자 데이터는 무결성이 보장되어야 한다.
3. **환경적 제약:** 클라우드 서버 환경(AWS/Azure 등)에서 원활하게 동작해야 하며, 다양한 웹 브라우저(Chrome, Safari 등)를 지원해야 한다.
