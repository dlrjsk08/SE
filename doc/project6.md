# 테스트 보고서 Mini Drive (미니 드라이브)

## 1. 서론

### 1.1 문서 목적 및 범위
* **문서 목적**: 본 문서는 개인용 클라우드 파일 공유 및 관리 시스템인 '미니 드라이브(Mini Drive)' 프로젝트의 최종 테스트 결과를 기록하고, 시스템이 초기 요구사항 정의서대로 안전하고 완전하게 구현되었는지 검증하는 데 목적이 있다.
* **범위**: 웹 프론트엔드 UI 대시보드 인터랙션, 백엔드 파일 처리 API 서버, 데이터베이스 연동 및 라즈베리 파이 실제 물리 스토리지 볼륨 제어를 포함한 시스템 전 과정을 범위로 한다.

### 1.2 프로젝트 개요
외부 상용 클라우드 서비스에 종속되지 않고 사용자가 상시 가동되는 독립된 파일 서버를 저전력 기기(라즈베리 파이 등)로 직접 운영하며, 웹 환경에서 데이터를 자유롭고 안전하게 관리, 저장, 공유할 수 있는 나만의 'Cloud File Sharing System' 구축 프로젝트이다.

### 1.3 용어 정의
* **미니 드라이브(Mini Drive)**: 라즈베리 파이 기반으로 제작된 개인용 저전력 독립형 클라우드 스토리지 시스템.
* **메타데이터(Metadata)**: 실제 파일 데이터 외에 데이터베이스에 기록되는 파일의 고유 속성 정보(파일명, 크기, 확장자, 업로드 일시 등).
* **청크 분할 전송(Chunking)**: 대용량 파일 전송 시 네트워크 부하와 타임아웃을 방지하기 위해 파일을 작은 조각 단위로 쪼개어 연속 전송하는 방식.
* **UUID 토큰**: 공유 링크 생성 시 외부 사용자가 임의로 주소를 유추하여 파일에 접근할 수 없도록 고유하게 발급하는 난수형 암호화 식별자.

### 1.4 참조 문서

## 2. 테스트 개요

### 2.1 테스트 범위
* **기능적 범위**: 파일 업로드(F01), 다운로드(F02), 메타데이터 관리(F03), 공유 링크 생성(F04), 용량 시각화(F05) 기능의 무결성 검증.
* **비기능적 범위**: Nginx 역방향 프록시 환경 기반의 SSL/TLS 전송 구간 암호화 및 무중단 서버 데몬 가용성 보장 상태 측정.

### 2.2 테스트 항목 및 통과 기준

| 테스트 ID | 테스트 항목 | 검증 세부 내용 | 통과 기준 (Pass Condition) |
| :---: | :--- | :--- | :--- |
| **TC-F01** | 파일 업로드 | 브라우저 인터페이스를 통한 스토리지 파일 전송 | HTTP 응답 코드 `201` 수신 및 실제 물리 볼륨 내 원본 파일 정상 생성 |
| **TC-F02** | 파일 다운로드 | 스토리지 보관 파일의 로컬 기기 다운로드 및 복원 | 원본 파일과 다운로드된 파일의 MD5 해시(Hash) 값이 100% 일치 |
| **TC-F03** | 메타데이터 관리 | 파일 상태 변경 시 DB 레코드 동기화 트래킹 | 업로드/삭제 이벤트 발생 시 SQLite/PostgreSQL 테이블 실시간 갱신 |
| **TC-F04** | 공유 링크 생성 | UUID 고유 토큰 주소 생성 및 게스트 접근 허용 | 익명/시크릿 브라우저에서 로그인 세션 없이 링크만으로 다운로드 성공 |
| **TC-F05** | 용량 시각화 | 스토리지 사용량 대시보드 차트 렌더링 검증 | 실제 디스크 용량 수치(`df -h`)와 웹 UI 차트 컴포넌트의 비율 일치 |
| **TC-N01** | 보안 및 가용성 | SSL/TLS 패킷 암호화 및 서버 가동 상태 트래킹 | HTTPS 트래픽 정상 암호화 확인 및 프로세스 강제 종료 시 자동 재시작 |

## 3. 테스트 케이스

### 3.1 테스트 케이스 선정
시스템 설계 단계에서 정의된 5개의 핵심 기능 요구사항과 주요 비기능 요구사항을 완벽히 충족할 수 있도록 상호 배타적이고 독립적인 시나리오를 기준으로 케이스를 선정함.

### 3.2 테스트 케이스 유형
* **기능(Functional) 테스트**: 정상/비정상 입력값에 따른 애플리케이션 인터랙션 및 입출력 제어 검증.
* **비기능(Non-Functional) 테스트**: 시스템 보안성(SSL/TLS), 가용성(자동 프로세스 재시작), 예외 상황에 대한 견고성 측정.

### 3.3 테스트 케이스 목록

| 케이스 번호 | 테스트 ID | 테스트 유형 | 테스트 케이스 명세 |
| :---: | :---: | :---: | :--- |
| **1** | TC-F01-01 | 기능 | 일반 크기 파일(텍스트, 이미지) 업로드 및 스토리지 적재 |
| **2** | TC-F01-02 | 기능 | 대용량 파일(1GB 이상) 업로드 시 청크 분할 전송 안정성 |
| **3** | TC-F02-01 | 기능 | 저장된 파일 목록 선택 후 로컬 기기로의 다운로드 실행 |
| **4** | TC-F02-02 | 기능 | 공백 및 특수문자가 포함된 파일명의 인코딩/디코딩 처리 |
| **5** | TC-F03-01 | 기능 | 파일 생성/삭제 발생 시 DB 메타데이터 테이블 정합성 트래킹 |
| **6** | TC-F04-01 | 기능 | 특정 파일의 UUID 기반 고유 토큰 외부 공유 링크 발급 및 익명 다운로드 |
| **7** | TC-F05-01 | 기능 | 스토리지 총용량 대비 실시간 잔여 용량 대시보드 차트 동기화 |
| **8** | TC-N01-01 | 비기능 | HTTPS 프로토콜 경유 전송 패킷 암호화 검증 |
| **9** | TC-N02-01 | 비기능 | 백엔드 웹 서버 데몬 프로세스 강제 종료 시 예외 복구력 |

## 4. 테스트 예외사항

### 4.1 중단 기준과 재개 조건
* **테스트 중단 기준**:
  * 라즈베리 파이 디바이스의 하드웨어 커널 크래시 또는 외부 전원 공급 중단으로 인한 인프라 다운 발생 시.
  * 백엔드 API의 치명적 결함으로 인해 데이터베이스(DB) 연결이 원천 불가능하여 메타데이터 저장이 전면 마비될 시.
* **테스트 재개 조건**:
  * 디바이스 재부팅 및 스토리지 볼륨 마운트 상태 정상 복구 확인 후.
  * 데이터베이스 인스턴스 초기화 핫픽스 적용 및 커넥션 풀 연결 정상화 완료 후 재개.
