# 요구사항 정의서: 미니 드라이브 (Mini Drive)

## 1. 서론

### 1.1 문서의 목적 및 범위
본 문서는 사용자가 개인용 클라우드 저장소를 구축하여 파일을 업로드, 다운로드 및 관리할 수 있는 **'미니 드라이브'** 프로젝트의 요구사항을 정의한다. 본 문서는 시스템의 기능적, 비기능적 요구사항과 인터페이스 요구사항을 상세히 기술하는 것을 목적으로 한다.

### 1.2 프로젝트 개요
* **프로젝트 정의**: 누구나 쉽고 저렴하게 자신만의 파일 서버를 구축할 수 있도록 라즈베리 파이 기반의 하드웨어 패키지와 이를 관리할 수 있는 웹 서비스를 제작한다.
* **주요 기능 설명**:

| ID | 기능 설명 |
| :--- | :--- |
| **F01** | 라즈베리 파이와 외장 스토리지를 활용한 파일 저장소 구축 |
| **F02** | 웹 브라우저를 통한 파일 업로드 및 다운로드 기능 제공 |
| **F03** | 업로드된 파일의 메타데이터(파일명, 크기, 생성일 등)를 DB에 저장 및 관리 |
| **F04** | 저장 공간 사용량 시각화 (대시보드 형태) |
| **F05** | 파일 공유 링크 생성 및 권한 설정 기능 |

### 1.3 용어 정의
* **스토리지**: 파일 및 데이터를 물리적으로 저장하는 장치나 공간을 의미한다.
* **메타데이터**: 데이터에 관한 데이터로, 파일의 이름, 크기, 유형 등 정보를 포함한다.

## 2. 요구사항

### 2.1 기능적 요구사항
1.  **사용자 계정 관리**
    * 사용자는 계정을 생성하고 로그인하여 자신만의 저장 공간에 접근할 수 있어야 한다.
2.  **파일 관리 기능**
    * 사용자는 다양한 형식의 파일을 업로드하고 관리할 수 있다.
    * 업로드된 파일 리스트를 확인하고 특정 파일을 로컬 기기로 다운로드할 수 있다.
    * 파일 삭제 및 폴더 생성 기능을 통해 저장 구조를 체계화할 수 있다.
3.  **공유 및 협업**
    * 특정 파일이나 폴더에 대해 외부 공유용 링크를 생성할 수 있다.
    * 공유 시 접근 권한(보기 전용, 편집 가능 등)을 설정할 수 있다.

### 2.2 비기능적 요구사항
* **보안성**: 모든 파일 전송은 암호화된 프로토콜을 사용해야 하며, 사용자 인증 없이는 데이터에 접근할 수 없어야 한다.
* **안정성**: 시스템 오류 발생 시 데이터 손실을 최소화하기 위한 백업 메커니즘이 고려되어야 한다.
* **성능**: 다수의 사용자가 동시에 접근하더라도 파일 탐색 및 기본 작업에 지연이 적어야 한다.

### 2.3 인터페이스 요구사항
* **웹 인터페이스**: 반응형 웹 디자인을 적용하여 데스크톱과 모바일 환경 모두에서 최적화된 화면을 제공해야 한다.
* **API 인터페이스**: 외부 애플리케이션과의 연동을 위해 RESTful API 규격을 준수한다.

## 3. 기타 요구사항
* **확장성**: 추후 대용량 스토리지 증설이 용이하도록 설계한다.
